# Nimble: open typed-decision model (GitHub)

Repository README for **Bespoke-Nimble-9B**, published by [[bespoke-labs|Bespoke Labs]] on 2026-09-18 — three days after [[typesafe-ai|TypeSafe AI]] announced [[jev|Jev]] — as an open alternative. 1,379 stars and 96 forks as of 2026-09-21. Python. **No license file** in the repository; the [[huggingface|Hugging Face]] weights are tagged Apache-2.0 (checked 2026-09-28), so the model is usable while the reference code carries no grant.

## What it claims

A [[lora|LoRA]] fine-tune of Qwen3.5-9B answers schema-declared questions by scoring one-token answer codes from the logits, returning typed values plus probabilities without generating any text. Training data comes from **contrastive data curation**: near-identical example pairs differing in one fact that flips the answer. 2,676 training examples, one epoch, LoRA rank 16, lr 5e-5, batch size 8, BF16.

Full mechanism, evaluation table and limits are recorded on [[nimble]].

## Why this source matters

It converts the System One claim from a vendor assertion into a reproducible recipe. [[typesafe-ai|TypeSafe]] published no architecture, no base model and no calibration curve; Bespoke published the data method, the hyperparameters and the eval harness. A 9B open model landing within 3.09 points of Jev on Jev's own kind of task is evidence that the capability is not exotic — the packaging is the product.

## What it does not show

The evaluation is self-constructed and **synthetic**: 324 examples, 162 contrastive pairs, six source families, reference labels generated by the same pipeline that made the training data. High agreement therefore measures reproduction of the label-generating process, not decision quality on real workloads. The comparison is also not run under uniform conditions — untuned baselines scored in FP32, Nimble in BF16, and the Jev and Nimble rows reused from earlier runs. The README notes a tie that broke differently on re-run, shifting the base model from 214 to 215 matches.

Nothing here validates [[calibration|calibration]] itself. The probabilities are normalized over the supplied answer set, and the README explicitly warns that 0.9 does not mean correct 90% of the time. No reliability diagram or ECE is reported for either model, so the central Jev claim — that the probabilities are trustworthy — remains untested by this source.

The claim that the team "did not distill from Jev" is a statement of intent, not something the artifact can prove; saved Jev probabilities did exist in the pipeline, reportedly unused as targets. See [[illicit-distillation]].
