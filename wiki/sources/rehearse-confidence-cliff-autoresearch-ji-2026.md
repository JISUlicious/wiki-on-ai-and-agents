# Rehearse: Stepping Back from the Confidence Cliff in Self-Improving Autoresearch

**Ji Jiazhen, Ding Shouhong** (Tencent) — [arXiv:2607.27687](https://arxiv.org/abs/2607.27687), cs.AI, 30 Jul 2026. Preprint; no venue given.

## Summary

"Autoresearch" here means the narrow, measurable-objective loop: an agent proposes a code modification to an ML repo, pays for a **full training run**, and keeps the edit only if the metric improves (Karpathy's nanochat loop is the reference instance). Every rejected modification burns a training run. The paper's question is not how to generate better ideas but whether the agent's **pre-execution judgment** — deciding *before* spending the run which candidate is worth it — stays reliable as the loop accumulates its own successes.

The answer is no, and this is the paper's headline **negative result**. Judging is measured under **strict consensus**: each pair is shown to the judge in both presentation orders and only counted when the two orders agree (otherwise it abstains). *Coverage* is the verdict rate; *selective accuracy* is accuracy conditioned on a verdict. Bucketing decisions by `n_baseline` (successful changes already in place), a memoryless judge holds **82.8% selective accuracy while little has accumulated and drops to 56.9% once three or more successes are in place** — a 25.9-point collapse — while its **coverage moves the wrong way, rising from 76% to 85%**. It becomes *more* willing to commit exactly as its verdicts become unreliable. The authors name this the **confidence cliff**.

The fix is deliberately small: **Rehearse** is shipped as a lightweight skill wrapped around an existing loop, not a fine-tune or a model rewrite. It converts one-idea-then-run into **Propose–Predict–Execute**: propose several candidate modifications, rank them with a pairwise judge before execution, run only the top *k* (all live runs use k=1), and write each executed attempt back to a **focused outcome store**. The store's design is the interesting part — retrieval returns only same-task attempts executed before the current step within cosine similarity **0.40**, serialized as one line of *change + binary outcome*. Nothing else. Late selective accuracy recovers to **83.5%**.

## Key points

**The cliff, and which history representation survives it** (Table 1; every single-turn number is a mean over three judge models — `hy3-preview`, `glm-5.1`, `deepseek-v4`; cliff bucket is `n_baseline ≥ 3`):

| Memory shown at decision | Overall sel. acc. | Cliff coverage | Cliff sel. acc. |
|---|---|---|---|
| No memory (full rationale, no history) | 77.6% | 85% | **56.9%** |
| Full-history dump (AIDE-inspired) | 82.0% | 80% | 70.8% |
| Self-reflection buffer (Reflexion-inspired) | 81.0% | **90%** | 74.1% |
| LLM summary of history | 81.9% | 78% | 80.9% |
| **Rehearse (focused retrieval)** | **82.3%** | **77%** | **83.5%** |

Two things to read off this table. First, **overall averages hide almost all of the failure** — the no-memory judge looks fine at 77.6% overall and is near-useless (56.9%) exactly where the loop needs it. Second, **more memory is not better**: the full dump and Rehearse draw from the *same* underlying store and differ only in that Rehearse shows a candidate-relevant slice; the dump loses 12.7 pp. Appending similarity-retrieved failure reasons to the full history recovers only to 73.3%.

**Judgment is genuinely useful when made explicit.** On the 296 strictly same-baseline **type-1** pairs (one modification improved the metric, one did not; both evaluated from the identical accepted baseline state, outcomes hidden, hypothesis field generated by a separate outcome-blind LLM), a judge with candidate rationales but no history reaches **79.5%** selective accuracy, rising to **84.2%** with the store. On the auxiliary 70-pair **type-2** probe (both worked; pick the larger gain) it is weaker but moves the same way, **67.4% → 74.1%**. The authors' own reading: the clean pre-execution signal is *classification* (likely-to-work vs. not), not fine ranking — filtering the many bad candidates recovers more compute than precisely ordering the few good ones.

**Ablations** (cliff bucket, leave-one-out from Rehearse's 83.5%):

| Configuration | Coverage | Sel. acc. |
|---|---|---|
| Rehearse (full) | 77% | **83.5%** |
| − candidate rationale | 78% | 70.2% |
| − idea text (→ similar-count only) | 80% | 70.8% |
| − focused retrieval (→ full dump) | 80% | 70.8% |
| − outcome label | 77% | 77.5% |
| − did-not-work precedents (worked only) | 82% | 78.9% |
| − worked precedents (did-not-work only) | 74% | 76.1% |
| − extra neighbors (top-1 only) | 77% | 80.5% |
| + recorded failure reason | 77% | 80.6% |
| + curated failure reason | 81% | 78.7% |
| No history (full rationale) | 85% | 56.9% |

Note the two *additive* rows: **explaining why past attempts failed makes the judge worse** (83.5 → 80.6, and 54.8% on the specific calls that carry such a reason). Rehearse therefore records only the change and its binary outcome.

**Live loops** — 100 experiments each, fixed 30-minute wall-clock budget per experiment, five seeds, **4,000 budgeted training runs total** (2,000 on nanochat = 4 configs × 5 seeds × 100; 2,000 across the two other loops). Four nanochat configurations share one idea-generating model and differ only in how the next step is chosen:

| nanochat config | Mean improvement over own baseline |
|---|---|
| vanilla (propose one, run it) | 7.1% |
| propose-many (propose several, run the first) | 6.9% |
| select (propose several, run the predict step's pick) | 8.4% |
| **Rehearse** (select + focused store) | **10.7%** |

Breadth alone buys nothing (6.9% vs 7.1%); **the selection step is what makes a wider pool useful** (+1.3 pp), and the store adds +2.3 pp on top, ahead on every seed.

**Generalization** to two unrelated loops, vanilla vs. Rehearse over five seeds each: CIFAR-10 accuracy **+2.85% vs +2.10%**; ETTh1 forecasting MSE cut **54.0% vs 40.1%**. Neither has a single dominant early change, so the curves track through the first half and separate late — after experiment 50 Rehearse realizes roughly **2–4.3×** vanilla's remaining gain (+0.7 vs +0.3 points on CIFAR, +17.7 vs +4.1 on ETTh1). Rehearse reaches vanilla's *final* level after **54 experiments on CIFAR and 63 on ETTh1** vs 100 for vanilla (46% and 37% fewer runs). Per seed, Rehearse ends ahead on 9 of 10 additional-loop runs.

**Two mechanism details worth keeping.** (1) The gain is not just abstention: on the deep calls *both* judges commit to, accuracy rises 63.4% → 82.5%, so the calls Rehearse declines are ones the memoryless judge mostly got wrong. (2) The store does **candidate-level** judgment, not direction-level blacklisting — lowering weight decay 0.2→0.15 was reverted while *raising* it was kept across three steps, and **87% of Rehearse's kept changes belonged to families that had also produced did-not-work attempts**. A naive "don't retry this family" heuristic would have thrown those away.

**Motivating observation** (from public AutoSOTA logs, not this paper's own runs): the fraction of helpful modifications falls from **70% in iterations 1–2 to 43% by iteration 6+**, and their mean gain shrinks from **3.6% to 0.3%**. Late-stage waste thus has two contributors — good ideas get rarer *and* the judge gets worse at spotting them.

**Stated limitations** — (1) five seeds per configuration, three loops, all with measurable outcomes; novelty- or paper-scored systems are out of scope. (2) Rehearse can only select from what the proposer generates; other memory forms and candidate-pool sizes are untested live. (3) Reported budgets **count training runs only** — proposal and judge inference are excluded, and the tournament costs 2·C(5,2) = 20 judge calls per step. (4) Most important: **`n_baseline` is observational**, so deep decisions may simply differ in headroom, modification family, and difficulty. The benchmark is a controlled proxy at run depth, not a randomized causal estimate of the cliff.

> [!warning] Qualifies the optimistic self-improvement pages
> [[self-improving-agent]], [[darwin-godel-machine]] and [[adas]] all describe an accept-if-it-scores loop where every proposed modification is *empirically trialed*. This paper measures the cost of that trial and shows the gate in front of it degrades with depth: the same judge that is 82.8% reliable at cold start is 56.9% reliable after three accepted changes, **while committing more often**. It does not refute self-improvement — it says reported gains should be read alongside how much compute the loop wasted late, and that carrying history as a raw trace (the standard practice in these loops) is the *worst* usable option in the deep regime.

> [!warning] Qualifies [[llm-as-a-judge]]
> The existing page records that a plain LLM judge degrades when given too much context ([[agent-as-a-judge]]: 84.15% → 68.86% when the trajectory is added). Rehearse finds a second, independent degradation axis: **judge reliability decays with the depth of the optimization trajectory it is judging within**, even when the per-call input is held fixed. And the judge does not signal it — coverage rises. Selective accuracy conditioned on a strict-consensus verdict is the metric that exposes this; a plain accuracy average does not.
